Your first React component: from Home.vue

We're porting the source app's Home page and app shell to React. So let's start where the real file starts: src/views/Home.vue in your Vue codebase. By the end of this ten-minute lesson you'll be able to read that SFC and write its React function-component equivalent skeleton from memory.

The one idea that unlocks everything

A React component is just a JavaScript function that returns JSX. Your component function runs on every render; React re-runs it whenever your component's state or props change. (Source: react.dev · Quick Start)

Compare that to Vue, where a component splits into <template>, <script>, and <style>, and where you rarely write the render function yourself. In React, the markup and the logic are the same thing: one function returning JSX. This is the mental-model shift from Vue to React.

Read the real file

Open src/views/Home.vue in the source Vue2 repo. Notice its shape:

  • <template> — the markup: a banner, widgets (userWelcome, teamWelcome), sliders, and a "what's hot" section with two tab buttons.
  • <script> — components registers children; data() holds newReleasesIsActive; computed/methods hold logic; created() runs once.
Vue: template, logic, style are separate blocks. Data is a reactive object; the framework handles re-rendering for you.

Translate it

Vue · Home.vue (abridged)

<template>
  <top-banner :id="bannerTopId" />
  <user-welcome />
  <team-welcome v-if="showTeamWelcomeWidget" />
  <compliace-slider />
  <my-training-slider />
  <button @click="activateNewReleases"
    :class="newReleasesIsActive ? 'active' : ''">
    New releases
  </button>
</template>

<script>
import TopBanner from "@/components/home/topBanner";
import UserWelcome from "@/components/home/userWelcome";
export default {
  components: { TopBanner, UserWelcome, ... },
  data() { return { newReleasesIsActive: false } },
  methods: { activateNewReleases(){ this.newReleasesIsActive = true } }
}
</script>

React · Home.tsx (translated)

import { useState } from "react";
import TopBanner from "./TopBanner";
import UserWelcome from "./UserWelcome";

export function Home() {
  const [newReleasesIsActive, setNewReleasesIsActive] = useState(false);

  const activateNewReleases = () =>
    setNewReleasesIsActive(true);

  return (
    <main>
      <TopBanner id={bannerTopId} />
      <UserWelcome />
      {showTeamWelcomeWidget && <TeamWelcome />}
      <ComplianceSlider />
      <MyTrainingSlider />
      <button
        onClick={activateNewReleases}
        className={newReleasesIsActive ? "active" : ""}>
        New releases
      </button>
    </main>
  );
}

Spot the patterns:

  • data() → useState: newReleasesIsActive becomes a [value, setter] pair.
  • methods → plain functions: activateNewReleases is just a function; it calls the setter instead of mutating this.
  • components + kebab tags → imports + PascalCase: import the function and use <TopBanner />.
  • v-if → {cond && ...}: plain JS.
  • :class → className: JSX uses className, not class.
  • @click → onClick: events are props, in camelCase.

Why this matters for your mission

Every screen in the source app — all 31 views and dozens of components — follows this same SFC shape. Once this single translation is instinctive, you can read any upstream component, and the "port" of the Home page becomes routine rather than mysterious. It's also the #1 thing an Australian React interviewer will watch you do fluidly.
