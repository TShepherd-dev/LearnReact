The Vite app shell: from main.js to main.jsx

This is the lesson that turns the four translations you've learned into a working app. You've translated components, effects, props and inputs. Now we stand up the actual shell — the part of the source app that launches the app, draws the header/menu/footer, and swaps views when you navigate. Mission milestone: “working Vite React app reimplementing the Home page + app shell.” This is where that becomes real. (Note: we’re doing this in plain JavaScript first — TypeScript is a later lesson, once the patterns are comfy.)

The one idea that unlocks the shell

Vue keeps mounting, layout and routing as framework magic: new Vue({router, store, i18n}).$mount('#app') cooks the app, and <router-view> swaps pages. React has no magic — you wire the same parts together with plain components and renders: createRoot(...).render(<App/>) starts it, a layout component wraps <Outlet/>, and the router just reads a route table. (react.dev createRoot · react-router declarative routing)

Read the real files

Three source files do all of this today:

  • src/main.js + src/appMounter.js — fetch startup settings, then new Vue({ router, store, i18n, render: h => h(App) }).$mount('#app').
  • src/frontend.vue — the shell template: <app-header />, <router-view />, <app-footer />, plus global overlays.
  • src/routers/core.js — the route table: path, name, component: () => import(...), and meta.uiMenu (with showInUI, displayOrder, menuIcon) that the header menu renders from.
the source app’s header menu is not a hardcoded list — it’s generated from each route’s meta.uiMenu. Add a route with showInUI: true and it appears in the menu. Your React port should keep that property: one route table drives both routing and the menu.

Translate it: the mount

Vue · appMounter.js (core)

const store = storeModule.createAndExportStore();
const router = routerModule.default;
const i18n = i18nModule.default;

const vm = new Vue({
  router,
  store,
  i18n,
  render: h => h(App)
}).$mount('#app');

React · src/main.jsx (full file)

import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import './index.css';
import App from './App';

createRoot(
  document.getElementById('root')
).render(
  <StrictMode>
    <App />
  </StrictMode>
);

Two things to notice:

  • $mount('#app') → createRoot(el).render(<App/>). Vue instantiates; React just renders a component tree into a DOM node. There is no separate “app object” — <App/> is a component like any other.
  • Router, store, i18n stop being constructor options. In React they become components/hooks you place inside the tree (<BrowserRouter>, Provider, hooks). That demotion is the whole React mental model: everything is just components.
  • main.jsx not main.js. The .jsx extension is the Vite convention for files containing JSX — plain .js still works, but modern React projects name it main.jsx.

Translate it: the shell layout

Vue · frontend.vue (template)

<app-header v-if="header" />
<router-view />
<app-footer v-if="footer" />

React · ShellLayout.jsx

import { Outlet } from 'react-router';
import ShellHeader from './ShellHeader';
import ShellFooter from './ShellFooter';

export function ShellLayout() {
  return (
    <>
      <ShellHeader />
      <main id="maincontent">
        <Outlet /> {/* matched page here */}
      </main>
      <ShellFooter />
    </>
  );
}

<router-view /> becomes <Outlet />. It’s the same contract — “render the matched child route here” — but Outlet is an ordinary component you place in ordinary JSX, so the shell layout is just a component.

Translate it: the route table + menu

Vue · routers/core.js (one route)

{
  path: '/',
  name: 'home',
  component: () => import('@/views/Home.vue'),
  meta: {
    uiMenu: {
      showInUI: true,
      displayLocation: 'menu',
      displayOrder: 1,
      menuIcon: 'fal fa-home fa-fw'
    },
    tkeys: { menuitem: "app.pageTitle.home" }
  }
}

React · App.jsx

import { BrowserRouter, Routes, Route } from 'react-router';
import { ShellLayout } from './ShellLayout';
import Home from './views/Home';

export function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route element={<ShellLayout />}>
          <Route index element={<Home />} />
          <Route path="notification"
                 element={<Notification />} />
          <Route path="my-training"
                 element={<MyTraining />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}

Spot the pattern:

  • A pathless <Route element={<ShellLayout />}> wraps the child routes. That’s the React way to get header+footer around a group — exactly what frontend.vue does with its root template. No <router-view>, just nesting.
  • path matches, element renders. path="notification" maps a URL segment to a component, same as Vue.
  • index route = the default child at / — our Home.
  • No meta.uiMenu yet. In React, keep the route table as data (see Reference 05) and build both <Routes> and the menu from the same array — that preserves the “menu derives from routes” behavior. Mock the i18n keys as plain strings for now.

Why this matters for your mission

This is the “app shell” half of “Home page + app shell”. Every source-app navigation goes through exactly these three pieces (bootstrap, shell, route table). An interviewer asking “walk me through how your app starts” is listening for createRoot/StrictMode/BrowserRouter in that order — it’s a stock question, and it’s the difference between “I’ve seen React” and “I’ve booted React”.

Do it in the real workspace

  1. In demo-react-app, rename/create the entry file to src/main.jsx and update it to the createRoot shape above (Vite’s JS template already gives you this shape — check main.jsx).
  2. Add react-router (npm i react-router). Create ShellLayout.jsx with ShellHeader, <Outlet />, ShellFooter.
  3. Rewrite App.jsx with BrowserRouter > Routes > [pathless shell > index Home].
  4. Bonus: replace the hardcoded nav in ShellHeader with a menuRoutes array that also feeds <Routes>.

Struggling to get it running? The createRoot/Outlet/Routes shape is the lesson — wire it in the existing Vite entry file that the template already gives you.
