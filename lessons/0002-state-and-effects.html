State & effects: what replaces created() and mounted()

Lesson 01 gave you the component shape. Now the second most common thing you'll translate when porting SourceApp: when does code run? Vue answers with named lifecycle hooks. React answers with one idea — useEffect. By the end of this lesson you'll be able to take any SourceApp view with created()/mounted()/beforeDestroy() and translate it to a single React effect plus its cleanup, from memory.

First, the mental-model shock

Vue splits when code runs into named hooks: created, mounted, updated, beforeDestroy. React has no lifecycle — your component function just runs on every render. When you want to sync with something outside the component (an API, a timer, a route), you use useEffect, and you tell it what changed with a dependency array. (react.dev · Lifecycle of Reactive Effects)

That sounds abstract. Let's make it concrete with a real SourceApp file — src/views/MyTraining.vue — which uses every lifecycle shape at once.

Read the real file

Open src/views/MyTraining.vue. Its script block has four of the five named hooks:

  • created() — reads this.$route.query.tab, updates route history.
  • mounted() — sets up global event handlers, starts a 30s polling timer (`updateScheduledTrainingCount`).
  • watch: "$route.query" — reacts when the tab query param changes.
  • beforeDestroy() — clearTimeout on that polling timer.
The timer is created in mounted() and cleared in beforeDestroy() — setup and teardown 60 lines apart. React joins them into one block.

Translate it

Vue · MyTraining.vue (relevant lines)

created() {
  if (this.$route.query.tab) {
    this.tab = this.$route.query.tab;
  }
  routerUtility.updateRouteHistory(
    this.$router.currentRoute);
},
mounted() {
  this.setupGlobalEventHandlers();
  this.setScheduledTrainingCount(0);
  this.updateScheduledTrainingCount();
},
beforeDestroy() {
  if (this.timer_updateScheduledTrainingCount) {
    clearTimeout(this.timer_updateScheduledTrainingCount);
  }
}

React · MyTraining.tsx (translated)

useEffect(() => {
  // created() + mounted() — run once
  setTabFromQuery(searchParams);
  updateRouteHistory(location);
  setupGlobalEventHandlers();
  updateScheduledTrainingCount();

  return () => {           // beforeDestroy()
    clearTimeout(timer);
  };
}, []); // empty deps = run once

Spot the shift:

  • created() + mounted() → one effect. React doesn't distinguish them. With [] the effect runs once, after first paint.
  • beforeDestroy() → a function you return. Whatever you return from the effect is the cleanup. React calls it on unmount — and also before every re-run (see below).
  • Setup and teardown move next to each other. No more hunting 60 lines for where the timer is cleared.

What about watch? The dependency array

The watch on $route.query is the key to the whole model. In React, an effect re-runs whenever anything in its dependency array changes:

Vue · watch a prop

watch: {
  "$route.query"() {
    if (this.$route.query.tab) {
      this.tab = this.$route.query.tab;
    } else {
      this.tab = "assigned";
    }
  }
}

React · effect with deps

useEffect(() => {
  setTab(searchParams.get("tab") ?? "assigned");
}, [searchParams]); // re-run when query changes

Same idea, new vocabulary: watch = effect with the watched value in the deps array.

Why this matters for your mission

Every interactive SourceApp screen touches state and timing — a created() that hydrates from route, a mounted() that subscribes, a beforeDestroy() that cleans up. In your port, every one of those files collapses into useEffect + cleanup. Interviewers will probe exactly this: “how do you make sure a subscription is cleaned up?” The answer — “the effect returns the cleanup” — is the single most important React answer to know cold.

Do it in the real workspace

  2. In your scratch project's src/MyTraining.tsx, transliterate only the lifecycle logic: one useEffect with [] that does the created+mounted work and returns a cleanup comment where beforeDestroy would clear the timer. Use … for the store calls you haven't learned yet.
  3. Now the twist — port the watch: "$route.query" as a second useEffect with [searchParams].

Two effects, one for the run-once setup, one for the route watch — that split is idiomatic React (organize by what you sync, not by when).
