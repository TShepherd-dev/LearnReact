Controlled inputs: what replaces v-model

You already translated structure (Lesson 01), timing (Lesson 02), and parent-child handshakes (Lesson 03). Now the last core piece of component behavior: forms. In Vue you type v-model="something" and the framework does both directions for you. React has no such sugar — and this is where new React devs panic. The good news: this codebase already writes the React pattern by hand. You’ll see it in 30 seconds.

The one idea

v-model is sugar for :value + @input. In React you write that handshake explicitly: value down as a prop, changes up as a callback. When an input’s text is entirely driven by React state, it’s a controlled component. (react.dev · <input>)

Notice the shape — value down, callback up. That’s exactly Lesson 03. Forms are not a new mechanism; they’re the same props handshake, applied to an <input>.

Read the real file

Open src/components/form/inputText.vue and src/components/myTeam/membersAddUserModal.vue. The first is SourceApp’s shared text field; the second is a modal form that uses it. This codebase does not use v-model on its inputs — it builds the handshake by hand:

  • inputText.vue exposes an inputValue prop and emits input-change with the new value.
  • membersAddUserModal.vue passes :inputValue="form.firstName || ''" down and listens for @input-change to write back.
Vue gives you v-model as a convenience on top of exactly this pattern. SourceApp chose to write the pattern out. React only has the pattern — so porting this file is almost literal.

Translate it

Vue · what you have

<input
  :value="inputValue"
  @input="$emit('input-change',
                $event.target.value)"
/>

<input-text
  :name="'firstName'"
  :inputValue="form.firstName || ''"
  :maxLength="20"
  @input-change="
    (val) => { form.firstName = val; }"
></input-text>

React · the same, in React’s own naming

const [form, setForm] = useState(initialForm);

<input
  name="firstName"
  value={form.firstName ?? ""}
  maxLength={20}
  onChange={(e) =>
    setForm({
      ...form,
      firstName: e.target.value
    })}
/>

inputValue became value; @input-change became onChange; $event.target.value became e.target.value. That’s the whole lesson — React’s plain <input> is SourceApp’s input-text, without the wrapper.

One detail to notice, because it trips people: setForm({ ...form, firstName: e.target.value }) replaces the whole form object with a copy that has one field changed. You do not set form.firstName = val — mutating state never re-renders. This is the immutable-update rule that replaced Vue’s reactive mutations.

Why this matters for your mission

Every admin screen in SourceApp is form-driven — user details, training plans, banners, system parameters, all backed by input-text / dropdown / checkbox. That’s why the codebase has 100+ usages. In a React port every one of those becomes a controlled component. And because the Vue side already does the explicit handshake, your job is XML-level naming: inputValue → value, input-change → onChange. You’ll look like a pro to an interviewer because you’ll say “controlled component” with the value/onChange shape instantly.
