The Home page: real layout + mock data

You already know the components (Lesson 01), the effects (02), the props flow (03), and state (06). Now we wire them together into the actual thing you set out to build: the Home page, matching the real layout, running off mock data. By the end of this lesson you'll be able to take any fed-by-the-store Vue page and turn it into a React page that loads its own data and hands it to child components as props.

The one idea

In Vue, a page pulls from a global store. In React, a page owns its data: a useEffect loads it, local state holds it, and the page passes it down to child widgets as props. Mock data is just a function that resolves to the same shape the real API would — so swapping for the real fetch later is a one-line change.

Read the real file

Open src/views/Home.vue in the source app. Notice how much of its script block is declaring data needs, not layout:

  • ...mapGetters("account", ["getCurrentUser", "isManager"])
  • ...mapState("account", ["metrics", "isMetricsLoading"])
  • ...mapState("catalogue", ["parentTags", "isParentTagLoading"])
  • ...mapActions("account", ["getMetrics"]) — fires the API call.

Then created() triggers getMetrics, and the template renders a stack of widgets (userWelcome, teamWelcome gated by isManager, sliders, and the “what’s hot” tab buttons flipping popularContentIsActive/newReleasesIsActive).

Translate it

Vue · Home.vue (data flow)

computed: {
  ...mapGetters("account", ["getCurrentUser","isManager"]),
  ...mapState("account", ["metrics","isMetricsLoading"]),
  ...mapState("catalogue", ["parentTags","isParentTagLoading"])
},
methods: {
  ...mapActions("account", ["getMetrics"])
},
created() {
  this.getMetrics();          // action fires API call
}

React · Home.jsx (translated)

export default function Home() {
  const [payload, setPayload] = useState(null);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    mockHome().then((data) => {
      setPayload(data);
      setIsLoading(false);
    });
  }, []);

  if (isLoading) return <p>Loading…</p>;

  return (
    <main>
      <UserWelcome user={payload.user} metrics={payload.metrics} />
      {payload.user.isManager &&
        <TeamWelcome user={payload.user} />}
      <WhatsHot />
    </main>
  );
}

Spot the pattern:

  • mapState / mapGetters → props. The store disappears from the widgets. Home holds the data and hands it down. Widgets become dumb prop-receivers.
  • mapActions + created() → useEffect. “Load on mount” is the same Lesson-02 effect; here it resolves a mock promise instead of calling the store action.
  • isMetricsLoading → isLoading local state, and the early-return <p>Loading…</p> does the v-if work.

The mock data contract

The trick that makes the demo run with no backend: the mock returns exactly the shape the real API returns. The component never knows the difference.

// mock/api.js
export const mockHome = () =>
  new Promise((resolve) => {
    setTimeout(() => {
      resolve({
        user: { firstName: "Tim", lastName: "Shepherd", isManager: true },
        metrics: {
          TotalModulesTaken: 12,
          TotalHoursTrained: 26,
          PlanCategoryProgress: [
            { PlanCategory: "compliance",   PlanCategoryProgressPercent: 60 },
            { PlanCategory: "trainingPlan", PlanCategoryProgressPercent: 40 }
          ]
        },
        parentTags: ["Compliance", "Leadership", "Safety"]
      });
    }, 400); // pretend network latency
});
The golden rule: match the real API's shape in the mock. Then “plumb in the backend” later means changing the import, not rewriting the page.

Widgets become prop-receivers

Vue · userWelcome.vue

computed: {
  ...mapGetters("account", ["getCurrentUser"]),
  ...mapState("account", ["metrics"])
}

React · UserWelcome.jsx

export default function UserWelcome({ user, metrics }) {
  const fullName = `${user.firstName} ${user.lastName}`;
  return (
    <div className="user-welcome">
      <h2>Welcome, {fullName}</h2>
      <p>You have {metrics.TotalModulesTaken} modules taken.</p>
    </div>
  );
}

Two rules:

  • The widget renders only what it's handed. No useContext, no store import — props only.
  • The page decides about missing data, not the widget. Early-return <p>Loading…</p> before rendering children.

Why this matters for your mission

This is the slice you picked to start with: the Home page and shell, with mock data. Every earlier lesson was scaffolding for this. When an interviewer describes a big legacy page fed by a store, your habit should be to ask — “what data does it need?” — and then write that as a single prop-shaped payload. That’s the React muscle.

Do it in the real workspace

  1. Open src/views/Home.vue in the source app and list its data needs (getters, state, actions) on paper.
  2. In your demo app, create src/mock/api.js with mockHome() returning the same shape (user, metrics, parentTags).
  3. Rewrite src/views/frontend/Home/Home.jsx: useEffect loads the mock, local state holds it, children rendered from props, with a Loading… early-return.
  4. Convert your existing widget components (TeamGreeting, etc.) into prop-receivers so Home — not the widget — owns the data.
