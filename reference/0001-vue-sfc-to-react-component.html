Vue SFC → React Function Component

How a Vue 2 single-file component maps onto a React function component using JSX and hooks. Read the corresponding lesson before relying on this; it is a quick-reference, not a tutorial.

The big shift

React components are JavaScript functions that return JSX. There is no <template>/<script>/<style> split by default — markup and logic live together. React runs your function on every render and re-renders when state changes. (react.dev)

Skeleton comparison

Vue · Home.vue

<template> ... markup ... </template>
<script>
export default {
  name: "home",
  components: { TopBanner, UserWelcome },
  data() { return { newReleasesIsActive: false } },
  computed: { ... },
  methods: { activateNewReleases() {} },
  created() { /* run once */ }
}
</script>
<style scoped> ... </style>

React · Home.tsx

import { useState } from "react";
import TopBanner from "./TopBanner";
import UserWelcome from "./UserWelcome";

export function Home() {
  const [newReleasesIsActive, setNewReleasesIsActive] = useState(false);

  // created()-equivalent:
  // const [x, setX] = useState(<init>); // or useEffect(fn, [])
  return ( /* JSX: markup + logic together */ <main>...</main> );
}

Lifecycle mental model

Vue splits when code runs into named lifecycle hooks (created, mounted, updated, destroyed). React replaces this with one idea: your component function runs on every render. Side effects are re-run by listing what changed in a dependency array. (Source: react.dev — Describing the UI, Lifecycle of Reactive Effects.)

Rules of Hooks

Hooks (useState, useEffect, ...) must be called at the top level of your component, unconditionally, in the same order every render. Don't put them in loops, conditions, or nested functions. If you need a condition, extract a component and put the hook there. (Rules of Hooks)
