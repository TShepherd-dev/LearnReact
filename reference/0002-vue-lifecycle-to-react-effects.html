Vue Lifecycle Hooks → React Effects

How Vue 2's lifecycle hooks (created, mounted, beforeDestroy, watch) map onto React's hooks — specifically useEffect. Read Lesson 0002 before relying on this; it's a quick reference, not a tutorial.

The mental model

Vue gives you named moments in a component's life and runs your code for you. React gives you one function that runs on every render, plus useEffect for synchronizing with the outside world — you tell React what changed, not when. There is no lifecycle. (react.dev · Lifecycle of Reactive Effects)

UseEffect fundamentals

Run once (created + mounted twin)

// Vue: created(){ ... } and mounted(){ ... } both fire once.
// React:
useEffect(() => {
  // runs after first render (painted DOM)
  updateRouteHistory(location);
  setParentTagLoading(true);
}, []); // <-- empty array = run once
The empty dependency array [] is what makes it run once. TypeScript note: ESLint may want to see the deps; it's legit for run-once setup.

Cleanup replaces beforeDestroy

// Vue: beforeDestroy(){ clearTimeout(this.timer) }
// React:
useEffect(() => {
  const timer = setTimeout(updateCount, 30000);
  return () => clearTimeout(timer); // <-- runs on unmount (and before every re-run)
}, []);

Re-run when a dependency changes (watch twin)

// Vue: watch: { "$route.query"(){ ... } }
// React:
useEffect(() => {
  setTabFromQuery(searchParams);
}, [searchParams]); // <-- re-runs after each render where searchParams changed

The cleanup sequence (why it's safe)

Vue · named moments

created()  → sets up
mounted()  → sets up (DOM ready)
…component lives…
beforeDestroy()
destroyed() → tears down

# “tear down” and
# “set up” are separate
# named blocks, called once.

React · one coupled unit

useEffect(()=>{
  // set up (every run)
  const t = setInterval(fn, 30000);
  return () => {
    // tear down (before every
    // re-run AND on unmount)
    clearInterval(t);
  };
}, []); // deps control re-runs

When deps change (or the component unmounts), React runs the previous cleanup first, then the new setup. So you can't "leak" a timer: every setup is paired with its teardown.

Rules that always apply

  • Effects run after render — never read imperative DOM that doesn't exist yet. Use useLayoutEffect only if a flash matters (rare).
  • Every effect that sets up something (timer, listener, subscription) must return a cleanup.
  • Cleanup runs on every re-run of the effect, not just unmount. This is stricter than beforeDestroy and it's a feature: stale dependencies get torn down, not accidentally left live.
  • “Run once” doesn't mean “first render only” — an effect with [] runs after the first committed render once.

When Vue code has multiple hooks

Real source files mix several hooks. You can put all of it in one useEffect when the setup/teardown share a lifecycle, or split into several effects when the concerns are different (e.g. one for the timer, one for route-sync). Splitting is idiomatic React — effects are organized by what they sync, not by when they run.
