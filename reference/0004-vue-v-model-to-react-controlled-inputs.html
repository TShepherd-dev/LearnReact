Vue v-model → React controlled inputs

How Vue’s v-model (and this codebase’s custom :inputValue/@input-change handshake) maps onto React’s controlled inputs. Read Lesson 0004 before relying on this; you already know the pattern from membersAddUserModal.vue.

The mental model

v-model is sugar for :value + @input. React ships no sugar — you write the handshake explicitly: value down, callback up. An input whose text is driven only by React state is a controlled component. (react.dev · <input>)

Term-by-term map

Vue 2ReactNotes
v-model="form.firstName"value={form.firstName ?? ""} onChange={...}No sugar: the value is a prop, the update is a callback.
:inputValue + @input-change (this repo’s custom handshake)value + onChangeSame shape as what you already write in membersAddUserModal.vue.
@input="$emit('input-change', $event.target.value)"onChange={(e) => setX(e.target.value)}Reading the DOM field’s value is the one imperative bit; everything else is data.
v-model checkboxchecked={x} onChange={(e) => setX(e.target.checked)}Checkbox uses checked, not value.
@input-change="(val) => form.firstName = val"setForm({ ...form, firstName: e.target.value })React state is replaced, not mutated: spread the object, patch one field.
form template + submit<form onSubmit={handleSubmit}>Call e.preventDefault() inside the handler.
uncontrolled inputdefaultValue + useRef if truly neededPrefer controlled; reach for this only when you must read the DOM.

Skeleton comparison

Vue · membersAddUserModal.vue

<input
  :value="inputValue"                 <!-- up in the comp -->
  @input="$emit('input-change',
                $event.target.value)"
/>

<input-text
  :inputValue="form.firstName || ''"
  @input-change="
    (val) => { form.firstName = val; }"
/>

React · MembersAddUserModal.tsx

const [form, setForm] = useState(initialForm);

<input
  value={form.firstName ?? ""}
  maxLength={20}
  onChange={(e) =>
    setForm({
      ...form,
      firstName: e.target.value
    })}
/>

Gotchas

  • Value must come from state. If only onChange is wired and value is missing, the DOM “wins” and the box becomes uncontrolled (React warns).
  • e.target.value is always a string. Convert if you need a number (Number(...)).
  • State objects are replaced, not mutated. Build a new object with spread: {...form, field} — mutation of form won’t re-render.
  • Checkbox ships checked, not value. Same callback, but the incoming value needs e.target.checked.
