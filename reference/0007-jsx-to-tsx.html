JSX → TSX: types define the component contract

How to move a Vite + React app from plain JSX to TypeScript, and how to type the pieces you've already built (props, hook state, reducer actions, route tables). A quick reference — read Lesson 0007 first.

The big shift

JSX is JavaScript with XML-ish markup. TSX is that same file with a compile-time type checker on top. Nothing about runtime behaviour changes — you get the same app — but the editor now turns "wrong prop name" and "wrong value shape" into red squiggles and a tsc failure instead of a confusing runtime undefined. Your 15 years of C# will feel at home: this is the compiler catching bugs before the browser runs. (typescriptlang.org)

Setup (once per project)

# in demo-react-app
npm i -D typescript          # @types/react & @types/react-dom already present

# tsconfig.json (Vite React template defaults)
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",          // automatic runtime — no "import React" needed
    "noEmit": true,              // Vite builds; tsc only type-checks
    "strict": true,
    "allowJs": true,             // let existing .jsx files keep working while migrating
    "skipLibCheck": true,
    "types": ["vite/client"],
    "isolatedModules": true,
    "verbatimModuleSyntax": true // type-only imports need "import type"
  },
  "include": ["src"]
}
Key invariant: with allowJs: true + checkJs: false, you can rename .jsx → .tsx and add types one file at a time. The app keeps running while you migrate.

Typing a component's props

JSX · Pagination.jsx (before)

export default function Pagination({ start, total, pageSize, onPage }) {
  const totalPages = Math.ceil(total / pageSize);
  const next = () => {
    if (start === totalPages) return;
    onPage(start + 1);   // onPage is *anything*
  };
  return (...);
}

TSX · Pagination.tsx (after)

type PaginationProps = {
  start: number;
  total: number;
  pageSize: number;
  onPage: (page: number) => void;
};

export default function Pagination(
  { start, total, pageSize, onPage }: PaginationProps
) {
  const totalPages = Math.ceil(total / pageSize);
  const next = () => {
    if (start === totalPages) return;
    onPage(start + 1);  // type-checked: must pass a number
  };
  return (...);
}

Now a parent that passes <Pagination total="one-hundred" /> or forgets onPage fails to compile. The prop list is the contract between components — TS makes it checked, not an afterthought.

Typing hook state and reducer actions

JSX · ShellCtxProvider.jsx (before)

const initialShellState = {
  header: true, showSideMenu: false,
  isSearchOpen: false, isMobileMenuOpen: false,
};
function shellReducer(state, action) {
  switch (action.type) {
    case 'showHeader': return { ...state, header: true };
    case 'setSideMenu': return { ...state, showSideMenu: action.show };
    case 'toggleSearch':
      return { ...state, isSearchOpen: action.open, isMobileMenuOpen: false };
    default: throw Error('Unknown: ' + action.type);
  }
}

TSX · ShellCtxProvider.tsx (after)

type ShellState = {
  header: boolean; showSideMenu: boolean;
  isSearchOpen: boolean; isMobileMenuOpen: boolean;
};

type ShellAction =
  | { type: 'showHeader' }
  | { type: 'setSideMenu'; show: boolean }
  | { type: 'toggleSearch'; open: boolean };

const initialShellState: ShellState = {
  header: true, showSideMenu: false,
  isSearchOpen: false, isMobileMenuOpen: false,
};
function shellReducer(state: ShellState, action: ShellAction): ShellState {
  switch (action.type) {
    case 'showHeader': return { ...state, header: true };
    case 'setSideMenu': return { ...state, showSideMenu: action.show };
    case 'toggleSearch':
      return { ...state, isSearchOpen: action.open, isMobileMenuOpen: false };
    default: throw Error('Unknown: ' + action.type);
  }
}

The discriminated union ShellAction is the C#-equivalent of typing each action — action.type pins which payload fields exist, so action.show inside the 'setSideMenu' case is typed, and a typo like 'showHeadder' is a compile error. useReducer(shellReducer, initialShellState) then infers dispatch to only accept valid actions.

Scope: one union per reducer (one per state slice/context) — not one per app, not per component. It is just a type in a file; export it and import it where that reducer's dispatch is used. Two slices = two unions. Components don't own unions, they consume them (calling dispatch with a union member, or reading slice State via a hook). The union's three jobs: a closed vocabulary of messages for the slice, per-message payload typing, and exhaustiveness (a new member flags every switch missing a case).

Typing the route table

JSX · ShellRouteTable.jsx (before)

const appRoutes = [
  {
    path: "/", name: "home",
    componentPath: "../views/frontend/Home/Home.jsx",
    meta: {
      menuOptions: {
        display: true, displayLocation: "topmenu",
        displayOrder: 1, menuIcon: "fal fa-home fa-fw",
        showSideMenu: false
      },
      tkeys: { menuitem: "app.pageTitle.home" }
    }
  },
  // ...
];

export default appRoutes;

TSX · ShellRouteTable.tsx (after)

export type MenuLocation = "topmenu" | "sidemenu";

export type AppRoute = {
  path: string;
  name: string;
  componentPath: string;
  meta: {
    menuOptions: {
      display: boolean;
      displayLocation: MenuLocation;
      displayOrder: number;
      menuIcon: string;
      showSideMenu: boolean;
    };
    tkeys: { menuitem: string };
  };
};

const appRoutes: AppRoute[] = [
  { path: "/", name: "home",
    componentPath: "../views/frontend/Home/Home.jsx",
    meta: { menuOptions: { display: true,
      displayLocation: "topmenu", displayOrder: 1,
      menuIcon: "fal fa-home fa-fw", showSideMenu: false },
      tkeys: { menuitem: "app.pageTitle.home" } } },
  // ...
];

export default appRoutes;

displayLocation: MenuLocation means ShellLayout's .filter(r => r.meta?.menuOptions?.displayLocation === 'topmenu') is now checked against a closed set — and consumers get autocomplete for exactly "topmenu" | "sidemenu".

One-file-at-a-time rule

Keep working while migratingHow
allowJs: true in tsconfigExisting .jsx files stay valid; TS doesn't check them (unless checkJs: true).
Rename .jsx → .tsx only when you're ready to type itOne component at a time; the app runs between steps.
Use import type for pure-type importsverbatimModuleSyntax requires it for erased-at-runtime imports.
Type public boundaries firstProps of leaf components + the route table give the most compile-time safety fastest.

Common gotchas

  • No import React from 'react' needed — with jsx: "react-jsx" the automatic runtime is implicit. (tsconfig jsx)
  • Event handlers: type them via the JSX element's inference — onClick={(e) => ...} — e is inferred as React.MouseEvent<...> automatically; you don't hand-write it.
  • State setters: useState(1) infers number; useState<number>(1) only needed when inference can't see the type.
  • If a parent passes the wrong prop type, fix the parent's call or the child's type — the error message names the file and line.
