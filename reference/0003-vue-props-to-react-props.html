Vue Props & Events → React Props & Lifting State

How Vue's props-down / events-up ($emit) data flow maps onto React, and why shared state ends up "lifted" into the parent. Read Lesson 0003 first; this is a quick reference.

One mental model: data flows down, callbacks flow up

Both frameworks agree on the shape: a child learns from its parent via props (read-only) and tells its parent about things via callbacks. Vue spells the callback as $emit('onPage', page); React spells it as an onPage prop the parent passes in. (react.dev · Passing Props)

Skeleton: child emits an event

Vue · pagination.vue (abridged)

props: { start: Number, total: Number, pageSize: Number },
methods: {
  next() {
    if (this.currentPage === this.totalPages) return
    this.currentPage += 1
    this.$emit('onPage', this.currentPage)
  }
}

React · Pagination.tsx

export function Pagination({
  start, total, pageSize, onPage
}) {
  const next = () => {
    if (currentPage === totalPages) return;
    onPage(currentPage + 1); // "emit" is a call
  };
  return ( /* JSX */ );
}

Skeleton: parent holds the state

Vue · assignment.vue (abridged)

<app-pagination
  :start="searchOptions.pn"
  :total="assignableTeamMembersTotal"
  @onPage="onPage"
  :pageSize="searchOptions.nr" />

methods: {
  onPage(currentPage) {
    routerUtility.saveScrollPosition()
    this.searchOptions.pn = currentPage
    this.$router.push({ query: { pn: currentPage } })
  }
}

React · Assignment.tsx

const [pn, setPn] = useState(0);

return (
  <Pagination
    start={pn}
    total={assignableTeamMembersTotal}
    pageSize={searchOptions.nr}
    onPage={(currentPage) => {
      setPn(currentPage);          // update lifted state
      navigate(`?pn=${currentPage}`);
    }}
  />
);

Lifting state, the short rule

If two sibling components both need the same value, the value lives in their closest common parent. The parent owns it with useState, passes the value down as props, and passes setter-callbacks down so children can request changes. (react.dev · Lifting State Up)

Common gotchas

  • Assigning to a prop: forbidden. In Vue 2 devmode you get a warning; in React it's silently ignored (and a bug).
  • Forgetting the callback: if a child needs to change shared state and you didn't pass it a callback, the child can't. That's the design — data flow is explicit.
  • Callback naming: onX for props, handleX for the handler in the parent is conventional but optional.
