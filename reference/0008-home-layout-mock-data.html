Home Page Layout + the Mock Data Contract

How the Vue 2 Home page (“read from the store, render a stack of widget components”) becomes a React page that loads a mock data module and distributes it to child components via props. Read Lesson 0008 first; this is the quick-reference.

The mental model

In Vue, a page pulls data from a global store (this.$store / map-helpers). In React, a page owns its loading: a useEffect fetches, local state holds the result, and the page passes that data down to child widgets as props. Mock data is just a function that resolves to the same shape the real API would — so swapping it for the real fetch later is a one-line change.

Where the real file reads data

In the source app, src/views/Home.vue declares its needs up front:

  • ...mapGetters("account", ["getCurrentUser", "isManager"])
  • ...mapState("account", ["metrics", "isMetricsLoading"])
  • ...mapState("catalogue", ["parentTags", "isParentTagLoading"])
  • ...mapActions("account", ["getMetrics"]) — triggers the API call

The page template is then a stack of widget components (userWelcome, teamWelcome, sliders, “what’s hot” tabs) plus local buttons that flip popularContentIsActive / newReleasesIsActive.

The mock data contract (the golden rule)

Write the mock to return exactly the shape the real API returns. The component should not know whether the data came from a file or a server. Swap = change one import. 
// mock/api.js  — same shape as the real /api/user/getMetrics
export const mockHome = () =>
  new Promise((resolve) => {
    setTimeout(() => {
      resolve({
        user: { firstName: "Tim", lastName: "Shepherd", isManager: true },
        metrics: {
          TotalModulesTaken: 12,
          TotalHoursTrained: 26,
          PlanCategoryProgress: [
            { PlanCategory: "compliance",     PlanCategoryProgressPercent: 60 },
            { PlanCategory: "trainingPlan",   PlanCategoryProgressPercent: 40 }
          ]
        },
        parentTags: ["Compliance", "Leadership", "Safety"]
      });
    }, 400); // pretend network latency
});
// components/Home.jsx — the page owns loading, then distributes
export default function Home() {
  const [payload, setPayload] = useState(null);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    mockHome().then((data) => {
      setPayload(data);
      setIsLoading(false);
    });
  }, []);

  if (isLoading) return <p>Loading…</p>;

  return (
    <main>
      <UserWelcome user={payload.user} metrics={payload.metrics} />
      {payload.user.isManager && <TeamWelcome user={payload.user} />}
      <WhatSHot onNewReleases setPopular… />   // or tab buttons
    </main>
  );
}

Widgets become prop-receivers

Vue · userWelcome.vue

computed: {
  ...mapGetters("account", ["getCurrentUser"]),
  ...mapState("account", ["metrics"])
}

React · UserWelcome.jsx

export default function UserWelcome({ user, metrics }) {
  // props arrived from Home — nothing reaches into a store
}

Two rules: (1) the widget takes everything it renders as props; (2) the page (not the widget) decides when data is missing — render early-return <p>Loading…</p> or null.

Loading-vs-content UI pattern

if (isLoading) return <div className="skeleton" />; // or text
if (!payload) return null;                           // nothing to show yet
