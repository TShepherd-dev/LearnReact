Vuex → React State Management

How a Vuex store (modules, state, getters, mutations, actions, map-helpers) maps onto React. Read Lesson 0006 before relying on this; it is a quick reference, not a tutorial.

The mental model

Vuex is a single global store outside your component tree that every component reaches into via this.$store / map-helpers. React has no built-in global store — state lives inside components. App-wide state is lifted to a provider higher up the tree and shared via Context; frequently-changing server data is owned by a query layer, not a store. (react.dev · Scaling Up with Reducer and Context)

First: what kind of state is it?

Kind of stateWhere it lives in ReactVuex habit to unlearn
Local to one component (tabs, form fields)useState / useReducer in that componentIn Vuex you'd often hoist even local toggles into a module; React keeps them local.
Shared app-wide client state (menu open, search open, notification count)Lifted to a provider: useReducer + Context (zero deps), or a Zustand store (~1.2 KB, no provider)This is the part that genuinely replaces a Vuex module.
Data fetched from an API (unread counts, listings, user)TanStack Query (cache, refetch, invalidation) or fetch-in-effect — not a client storeVuex actions did API + caching duty; in React 2026 that is server state, not store state.

Term-by-term map (module → reducer + context)

Vuex · store/shell.js (abridged)

export default {
  namespaced: true,          // "shell."
  state: {
    footer: false,
    header: false,
    isSearchOpen: false,
    isMobileMenuOpen: false,
    isProfileDropdownOpen: false,
    notificationCount: 0
  },
  mutations: {
    showFooter(state) { state.footer = true },
    toggleSearch(state, open) { state.isSearchOpen = open },
    setNotificationCount(state, n) { state.notificationCount = n }
  },
  actions: {
    toggleSearch({ commit }, open) {
      commit('toggleSearch', open);
      commit('toggleMobileMenu', false);
      commit('toggleProfileDropDown', false);
    }
  },
  getters: { getAllowTranslations: s => s.allowTranslations }
}

React · ShellContext.jsx

const ShellCtx = createContext(null);

function shellReducer(state, action) {
  switch (action.type) {
    case 'showFooter': return { ...state, footer: true };
    case 'toggleSearch':
      return { ...state, isSearchOpen: action.open,
               isMobileMenuOpen: false,
               isProfileDropdownOpen: false };
    case 'setNotificationCount':
      return { ...state,
               notificationCount: action.count };
    default: throw Error('Unknown: ' + action.type);
  }
}

export function ShellProvider({ children }) {
  const [state, dispatch] = useReducer(shellReducer, {
    footer: false, header: false,
    isSearchOpen: false, isMobileMenuOpen: false,
    isProfileDropdownOpen: false, notificationCount: 0
  });
  return (
    <ShellCtx value={state}>
      <ShellDispatchCtx value={dispatch}>{children}</ShellDispatchCtx>
    </ShellCtx>
  );
}
export const useShell = () => useContext(ShellCtx);
export const useShellDispatch = () => useContext(ShellDispatchCtx);

Context 101 (the “pass without prop drilling” part)

  • Context is dependency injection: a provider makes a value available to the whole subtree; any descendant reads it with useContext.
  • Every consumer re-renders when the provider value changes — fine for menu/search toggles; a performance trap for high-frequency updates (that’s the Zustand/selector case).
  • Convention (from the React docs): keep two contexts — one for the value, one for the dispatch function — plus a useX()/useXDispatch() hook pair per file.

Put a library on it? (2026 reality)

  • App-wide UI state, want zero deps: reducer + context (what this sheet shows).
  • App-wide UI state, want lean & widely-used: Zustand 5 — ~1.2 KB gzipped, no Provider needed, selector-based subscriptions re-render only what reads the changed slice. The 2026 de facto standard for client state.
  • Large multi-team app needing audit trails/time-travel devtools: Redux Toolkit (still the enterprise standard).
  • Anything fetched from an API: TanStack Query, not the store.
