Auth & routing: guards, context, return-referrer

Vue guards navigation inside the router (imperative router.beforeEach); React guards navigation by deciding what renders (a component in the route tree). This is the quick-reference for porting the auth gate from src/routers/core.js + src/store/bffAuth.js. Read Lesson 0010 first.

The mental model

router.beforeEach runs its check once per navigation, as a side effect. A <RequireAuth> component re-runs its check on every render. So when the user logs in or out, the tree reacts on its own — no second navigation is needed, and there is nowhere a guard, a login page, and a logout page can disagree.

The same decision, two homes

Vue · the source app

router.beforeEach((to, from, next) => {
  const authRequired = to.matched
    .some(r => !r.meta.isPublic);

  if (authRequired &&
      !store.getters['account/getCurrentUser']) {
    store.dispatch('bffAuth/login'); // full-page OIDC redirect
    return next(false);              // drop this navigation
  }

  sessionStorage.setItem(
    'requestedPath', to.fullPath);   // remember where to return
  next();
});

React · the ported app

function RequireAuth() {
  const { user } = useAuth();
  const location = useLocation();

  if (!user) {
    return <Navigate to="/login"
      state={{ from: location }}
      replace />;
  }
  return <Outlet />;
}

// route tree (App.jsx)
<Route element={<RequireAuth />}>
  <Route element={<ShellLayout />}>
    <Route index element={<Home />} />
    <Route path="my-training"
      element={<MyTraining />} />
  </Route>
</Route>

The mock BFF contract

The mock impersonates the real BFF auth endpoints (/bff/login, /bff/session, /bff/logout) — same resolve shapes, able to reject. Going live is a one-line import swap, exactly like Lessons 0008/0009. 
// src/mock/auth.js
export const mockBff = {
  getSession: () =>
    Promise.resolve({ isAuthenticated: false, user: null }),
  login:      () =>
    Promise.resolve({ id: 5402, name: 'Tim' }),
  logout:     () => Promise.resolve(),
};

Rules to remember

  • A guard is a component: it returns <Navigate> for guests or <Outlet /> for everyone else.
  • Carry the intended destination in location state, not sessionStorage — and use replace on both sides so the Back button never lands on /login.
  • Render a boot/splash until the session check settles. Protected UI must never flash before the auth answer.
  • Auth state lives in one context so RequireAuth, Login and Logout are always consistent.
  • Client redirects are UX, not security. The source app is explicit: its route permissions exist only to control UI route access in the browser — the API/BFF enforces the real boundary. (2026 data-mode React Router does the same steering with throw redirect('/login') in a loader or middleware.)
