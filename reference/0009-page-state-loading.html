Page data states: loading, empty, error, retry

How the Vue page’s store loading flag and the app’s global axios error interceptor become states the React page owns itself. Read Lesson 0009 first; this is the quick-reference.

The four states a data-fed page can be in

StateTriggerWhat the user sees
Loadingrequest started, not finishedspinner / skeleton / “Loading…”
Successpromise resolved with datathe real content
Emptyresolved, but zero recordsfriendly “nothing here yet” message
Errorpromise rejectederror message + Retry button

Vue vs React: where error handling lives

Vue · the source app

// store: loading flag lives in Vuex
getMetrics({ commit }) {
  commit('setMetricsLoading', true);
  return api.get('api/user/getMetrics').then((data) => {
    if (data.Output) commit('setMetrics', data.Output);
  });
  // no .catch — the page never sees a failure
}

// axios.config.js: errors surface GLOBALLY
// 500 -> safeShowGrowlMessage('warning',
//   'An application error occurred...')
// 401 -> silent retry after 2s

React · the ported page

const [payload, setPayload] = useState(null);
const [isLoading, setIsLoading] = useState(true);
const [error, setError] = useState(null);

const load = () => {
  setIsLoading(true); setError(null);
  mockHome()
    .then(setPayload)
    .catch((err) => setError(err))
    .finally(() => setIsLoading(false));
};
useEffect(() => { load(); }, []);

if (isLoading) return <p>Loading…</p>;
if (error) return (
  <p>Something went wrong.</p>
  <button onClick={load}>Retry</button>
);
if (!payload.whatsHotModules.length) {
  return <p>No content yet.</p>;
}

The Vue app routes every failure through one central interceptor, so the page stays dumb. React hands the failure back to the page as a rejected promise, and the page decides what to render — including the Retry button.

The mock contract, extended

The mock mimics the real API’s contract — not just its happy path. If the real endpoint can fail, the mock must be able to reject too, or the error and retry branches are untested fiction. (Source: Lesson 0008’s golden rule — “the component should not know whether the data came from a file or a server” — extended to failure.) 
export const mockHome = (opts) =>
  new Promise((resolve, reject) => {
    setTimeout(() => {
      if (opts && opts.fail) {
        reject(new Error('network down'));
        return;
      }
      resolve({ /* same shape as the real API */ });
    }, 400);
  });

Rules to remember

  • One page, one load function. The effect calls it; the Retry button calls it. Never write the fetch twice.
  • Order the early returns: loading first, then error, then empty, then content.
  • Resetting: at the start of load, clear error so a retry doesn’t keep showing the stale message.
  • Production note: for real server data at scale you reach for TanStack Query’s useQuery, which bakes in all four states — but the state-machine understanding is the same. (react.dev: don’t hand-roll fetching in shipped apps; lesson 0006’s server-state split.)
