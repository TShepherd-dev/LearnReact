App shell & routing: mounting, layout and the route table

How the source app’s bootstrap (src/main.js, src/appMounter.js), frontend shell (src/frontend.vue) and route table (src/routers/core.js) map onto a Vite React app (plain JavaScript for now — TypeScript is a later lesson). Read Lesson 0005 first; this is a quick-reference.

The mental model

In Vue, the app is started (a Vue instance with router/store/i18n plugged in) and pages are swapped by a magic <router-view>. In React, everything is component composition: createRoot(...).render() kicks it off, a shell component renders <Outlet/> where pages appear, and the route table is just data you feed to the router. (react.dev · createRoot, react-router · Declarative routing)

Bootstrap

Vue · main.js + appMounter.js

import Vue from 'vue';
const store = createAndExportStore();
const router = routerModule.default;
const i18n = i18nModule.default;

new Vue({
  router, store, i18n,
  render: h => h(App)
}).$mount('#app');

React · src/main.jsx

import { createRoot } from 'react-dom/client';
import { StrictMode } from 'react';
import App from './App';

createRoot(
  document.getElementById('root')
).render(
  <StrictMode>
    <App />
  </StrictMode>
);

Shell: header + routed page + footer

Vue · frontend.vue

<app-header v-if="header" />
<router-view />
<app-footer v-if="footer" />

React · ShellLayout.jsx

import { Outlet } from 'react-router';
import ShellHeader from './ShellHeader';
import ShellFooter from './ShellFooter';

export function ShellLayout() {
  return (
    <>
      <ShellHeader />
      <main id="maincontent">
        <Outlet /> {/* page goes here */}
      </main>
      <ShellFooter />
    </>
  );
}

Route table

Vue · routers/core.js

const router = new VueRouter({
  mode: 'history',
  routes: [
    {
      path: '/',
      name: 'home',
      component: () => import('@/views/Home.vue'),
      meta: {
        uiMenu: {
          showInUI: true,
          displayLocation: 'menu',
          displayOrder: 1,
          menuIcon: 'fal fa-home fa-fw'
        },
        tkeys: { pagetitle: "...home", menuitem: "...home" }
      }
    }
  ]
});

React · App.jsx (React Router)

import { BrowserRouter, Routes, Route } from 'react-router';

export function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route element={<ShellLayout />}>
          <Route index element={<Home />} />
          <Route path="notification"
                 element={<Notification />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}

Menu from route meta (the pay-off)

the source app’s header is generated from meta.uiMenu (showInUI/displayOrder/menuIcon), not hardcoded. In React, keep the route table as data; build both <Routes> and the menu from the same array so a new page shows up in the menu for free:

const menuRoutes = [
  { path: "/", label: "Home", icon: "home", element: Home },
  { path: "/my-training", label: "My training", icon: "book", element: MyTraining }
];

// ShellHeader maps it:
<nav>{ menuRoutes.map(r => <Link key={r.path} to={r.path}>{r.label}</Link>) }</nav>

// App.jsx can derive the <Routes> from the same array.
// (TypeScript would type this array as a "MenuRoute" shape — later lesson.)

Versions to know (2026)

  • React Router is now split into declarative (<BrowserRouter>/<Routes>) and data (createBrowserRouter/RouterProvider, loaders/actions) modes. For a mock-data port, declarative is plenty.
  • Install is npm i react-router (react-router-dom is gone in v8; imports come from react-router).
  • main.jsx is the Vite entry convention for JSX files; .tsx (TypeScript) comes in a future lesson.
  • Vite’s React JS template already ships the createRoot(<App/>) entry — the shell lesson mostly asks you to add routing around it.
